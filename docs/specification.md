# notion-sync 仕様書

この文書は、2026-11-03 時点のリポジトリの実装を記述する。利用手順は [README](../README.md)、開発時の注意事項は [AGENTS.md](../AGENTS.md) を参照する。

## 1. 目的と範囲

ローカル Markdown を Notion のページまたはデータベース（DB）へ同期する CLI。基本はローカルから Notion への一方向で、明示的な `--pull` では対応する変更を取り込む。検索、閲覧、非管理ページの作成、同期状態の復旧・解除も提供する。認証と API 呼び出しには公式 CLI `ntn` を使う。

### 動作環境

| 項目 | 仕様 |
| --- | --- |
| 実行環境 | Go 1.27 以上。`go.mod` の toolchain は 1.27.3 |
| 認証 | ユーザーが `ntn login` または `notion-sync auth login` で実施 |
| Notion CLI | `ntn` 0.23.25 で動作確認 |
| API バージョン | `2026-03-11` |
| 同期対象 | 同期元配下の Markdown ファイル。シンボリックリンクは走査しない |

既定の同期元 `./docs` には、この仕様書も含まれる。

## 2. コマンド

| コマンド | 機能 |
| --- | --- |
| `init` | `.env` のひな形を新規作成。既存ファイルは上書きしない |
| `auth login` / `auth status` | `ntn` によるログイン / 認証状態の確認 |
| `doctor` | `ntn` と認証、指定した親の読み取りアクセスを確認。書き込み権限は確認しない |
| `search <query>` | ページとデータソースをタイトルで検索 |
| `page list` / `page view <page>` | ページ一覧 / Markdown 表示 |
| `page create` | 親ページの下に非管理ページを作成 |
| `db list` / `db query <database>` | DB 一覧 / 単一データソースの DB 項目一覧 |
| `db create <database>` | DB に非管理項目を作成 |
| `sync [source]` / `diff [source]` | ディレクトリの同期 / 変更予定と差分の表示 |
| `page sync <file>` / `page diff <file>` | 単一ファイルの同期 / 変更予定と差分の表示 |
| `recover <file>` | 作成結果が不明なページを調査後、保留状態を解決 |
| `reset <file-or-directory>` | ローカルの同期先 ID と同期情報を消去。Notion は変更しない |

作成コマンドは同期対象を登録しない。検索・一覧の `--limit` は 1〜1000、既定値は 50。対応コマンドでは `--json` を使える。ページや DB はコマンドにより ID・Notion URL・一意な完全タイトルで指定できるが、`--parent-id` は ID のみ。

## 3. 設定と入力

設定の優先順位は、コマンドオプション、環境変数、`.env`、既定値の順とする。`.env` の場所は `--env-file` で変更できる。ファイル単位の同期先指定は既定の親より優先される。

| 設定 | 環境変数 | 既定値 |
| --- | --- | --- |
| 同期元 | `NOTION_SYNC_SOURCE` / `--source` | `./docs` |
| 既定の親 | `NOTION_SYNC_PARENT_ID` / `--parent-id` | なし。同期時に必要 |
| 親の種別 | `NOTION_SYNC_PARENT_TYPE` / `--parent-type` | `auto`。`page`、`db` も指定可 |
| ディレクトリ階層 | `NOTION_SYNC_PRESERVE_HIERARCHY` / `--preserve-hierarchy` | `true` |
| draw.io 埋め込み | `NOTION_SYNC_DRAWIO_EMBED` / `--drawio-embed` | `false` |
| メタデータ形式 | `NOTION_SYNC_METADATA_FORMAT` / `--metadata-format` | `comment`。`frontmatter` も指定可 |
| 対象パターン | `NOTION_SYNC_INCLUDE` / `--include` | `**/*.md` |
| 除外パターン | `NOTION_SYNC_EXCLUDE` / `--exclude` | `**/node_modules/**` |
| アイコン | `--icon` | 指定なし |
| DB プロパティ | `--property` | 指定なし。複数指定可 |

`page sync`、`page diff`、`recover` では、同期元が別途設定されていなければ対象ファイルの親ディレクトリを同期元とする。対象ファイルは設定された同期元の内側に存在する必要がある。

### ファイル単位の指定

既存ページや新規作成先は、frontmatter またはファイル先頭の `<!-- notion-sync ... -->` に `notion-page-id`、`notion-parent-page-id`、`notion-database-id` で指定できる。親ページ ID と DB ID は同時指定できない。

新規ページのタイトルは本文の最初の H1 見出し、なければファイル名とする。既存ページのタイトルは同期で変更しない。ページを親とする同期では、設定に応じてディレクトリ階層を再現する。DB を親とする同期では、配下のファイルを同じ DB の項目として作成する。

## 4. 同期処理

### 4.1 計画と実行

1. 設定・ファイル・共有状態とアクセスを確認し、同期先、本文、メディア、リンク、DB プロパティ、アイコンとロックの変更を計画する。
2. `diff` / `--dry-run` は計画を表示し、Notion、ローカル Markdown、共有状態を変更しない。
3. 実行時は相互参照を解決するため新規ページを先に作成し、必要なページを再計画して本文を同期する。既存ページの更新前には親や本文などを再確認する。
4. ページ ID、親、本文やメディアのハッシュなどを保存する。

### 4.2 競合と上書き

同期済みページでは、保存された親と Notion の親を比較し、移動が検出された場合は停止する。本文は保存済みのリモートハッシュを基準に変更を検出する。既存ページを初めて指定する場合は、本文が空かローカル本文と一致するときのみ同期する。

Notion 本文の競合時は差分を表示して停止する。`--push` は競合する対象ページをローカルの内容で置き換える。`--overwrite` は旧名の別名である。`--push` の対象は指定した同期範囲全体となる。端末の差分表示は色と行番号を使用し、リダイレクト時は行番号と色を付けない。`NO_COLOR` は色を無効にする。表示用の正規化と競合判定は同一ではない。

Notion の読み取りと更新、ローカルファイルの確認と置換の間には競合の余地がある。ローカルファイルが処理中に変わったことを検出した場合は停止する。

### 4.3 `--pull`

`--pull` は、同期済みで Notion 本文が前回から変更されたファイルのみを対象とし、Notion に書き込まない。ローカルにも異なる未同期変更がある場合や、変更されたリンク・メンションを安全に変換できない場合は停止する。

- ディレクトリの pull は、画像・ファイル・HTML コメントを含むページに対応しない。`--drawio-embed` と併用できない。
- 単一ファイルは、元の本文と画像参照を検証でき、変更が末尾へのテキスト追加に限定される場合に限り、画像・管理対象 draw.io 埋め込みを保持できる。画像や埋め込みの変更、本文途中の編集、追加されたリンクや HTML などは停止する。
- `--pull` は `--push`、`--icon`、`--property` と併用できない。単一ファイルでは `--replace-drawio-embeds` とも併用できない。

## 5. ページ設定と DB プロパティ

### 5.1 ロックとアイコン

新規ページ、および同期対象の既存ページは Notion UI の編集ロックをオンにする。ロックは Notion API 経由の更新を妨げない。`--dry-run` はロック予定を表示する。

`--icon <name>` は Notion 組み込みアイコンを既定色で設定する。新規ページだけでなく、同期対象の既存ページやディレクトリ用ページにも適用する。指定しない場合、既存アイコンを保持し、新規ページにはアイコンを指定しない。

`--icon random` は確認済みの組み込みアイコン 16 種から選ぶ。同期時の選択は親 ID とファイルまたはディレクトリのパスから決まり、同一対象への再同期では変わらない。`page create` / `db create` では作成ごとに選ぶ。dry-run は同期時に選ばれる名前を表示する。変更対象の既存アイコンは上書きされる。

### 5.2 DB プロパティ

DB のスキーマにあるプロパティ名を frontmatter または `notion-sync` HTML コメント内の `notion-properties` に指定できる。両方に同時に定義した場合はエラーとする。`--property '名前=値'` は繰り返し指定可能で、同名のファイル内の値より優先し、実行時に対象 Markdown の指定されたメタデータ形式にも書き込む。同期時には既存の `notion-properties` も指定された形式に移し、reset 時は値を保持する。値中の空白はシェルの引用符で保持する。対象外または未指定の DB プロパティは変更しない。

| 型 | 指定方法と制限 |
| --- | --- |
| `rich_text` | 文字列。最大 2,000 文字 |
| `number` | 数値または数値文字列 |
| `checkbox` | 真偽値または真偽値文字列 |
| `date` | 開始日のみ。既存の日付範囲やタイムゾーン付き値は処理を停止 |
| `select` / `status` | DB に存在する選択肢の名前 |
| `multi_select` | 文字列配列、またはカンマ区切り文字列。値全体を置き換える |
| `url` / `email` / `phone_number` | 文字列 |

リレーション、ユーザー、ファイル、読み取り専用型などは未対応。タイトルは本文から決め、`notion-properties` では変更しない。未知のプロパティ、型、選択肢はエラーとする。既存ページは対象プロパティの計画時と更新直前の値を比較し、変化していた場合は停止する。更新応答も確認する。

実行時、`--property` によるローカルのプロパティ更新は Notion のプロパティ更新より先に行う。途中で失敗した場合、ローカルだけが更新済みとなることがある。YAML の書式は再出力時に変わる場合がある。

## 6. Markdown、リンクとメディア

### 6.1 本文とリンク

HTML コメントは同期本文から除外するがローカルには保持する。コードブロック・インラインコード内のコメント例は保持する。Markdown の変換は Notion API の対応範囲に依存する。

同期元内の Markdown への相対リンクは、対象ページ ID が分かる場合にページメンションへ変換する。見出し付きリンクは `表示名 - ページメンション` に変換し、特定の見出しへは移動しない。対象外・未同期の見出しリンクは文字列として残し、クエリ付きの内部リンクは変換しない。元の Markdown は書き換えない。

同期元外への相対リンクは、GitHub `origin` がありリンク先が現在の `HEAD` に含まれる場合、そのコミットの GitHub URL に変換する。解決できない場合はリンク記法を文字列として同期する。生成 URL はコミット済みの内容を指す。

### 6.2 画像・動画

- 画像は単独行の `![説明](相対パス)`、動画は単独行の `[説明](相対パス)` または画像形式の MP4 参照で指定する。
- ファイルは同期元内の通常ファイルに限る。画像は PNG、JPEG、GIF、WebP、SVG に対応し、各 20 MB 以下とする。
- MP4 は 20 MiB を超える場合に分割アップロードする。Notion ワークスペースの上限も適用される。
- 未変更の画像は再アップロードしない。画像だけが変更された場合、安全に対応付けられる既存ブロックを更新する。曖昧な参照や検証不能な URL は停止する。
- 本文変更時は本文とローカル画像を順序どおり再作成する。ローカル画像・draw.io 埋め込みの削除は `--push` 指定時に本文全体を再作成する。dry-run で確認する。アップロードや更新の結果が不明な場合は再試行前に Notion で確認する。

### 6.3 draw.io

通常の `.drawio.svg` は、アップロードするコピーからルート要素の `content` 属性を除去する。元ファイルと変更検知用ハッシュは保持する。Notion に保存された SVG には編集データが含まれない。

`--drawio-embed` は `private-diagram-viewer` の `drawio-to-html` から取り込んだ変換処理を使い、共有状態と同じ同期元別ディレクトリに `<元ファイル名>.html` を出力する。HTML を `text/html` でアップロードし、API `2026-03-11` の `embed.file_upload` に指定して Notion の HTML ブロックを作成する。URL の手動貼り付けは不要。HTML 内には元 SVG と編集用 XML を保持し、コマンド出力には保存先のみ表示する。期限付き取得 URL は初回同期から管理対象ブロックだけを正規化してハッシュ化し、URL の更新による競合を防ぐ。

`sync` と `page sync` の共通計画で、空または `viewer.diagrams.net` の旧形式の管理対象ブロックを検出する。本文が未変更でも HTML をアップロードし、既存ブロックの `embed.file_upload` だけを更新する。本文・ブロック ID・キャプションは保持し、dry-run に移行対象を表示する。対象はローカル画像参照と対応付けられるブロックに限り、更新前後にブロック・本文の競合と読み戻しを検証する。不明な結果を再試行しない。既存の HTML やその他の URL 埋め込みは保持し、移行後の図の変更は通常同期しない。図のハッシュが一致し HTML ファイルがない場合は再生成する。再生成できなければ警告して同期を続ける。既存の HTML ファイルと旧 `.txt` は変更しない。新規生成・置換時に同名の HTML が異なる内容なら、dry-run を含め Notion 書き込み前に停止する。

埋め込みを保持したまま更新できない場合は対象ページをスキップする。`--drawio-embed --push --replace-drawio-embeds` は、対象ページの本文全体と埋め込みを再作成し、生成した HTML を自動アップロードして設定する。

SVG の標準 DOCTYPE（PUBLIC / SYSTEM を含む）を許可し、内部 DTD 定義、重複宣言、ルート後の宣言は拒否する。外部 DTD・実体の取得や展開は行わない。HTML のビューアーと図形定義バンドルは固定版 draw.io v32.6.10 を SRI 付きで CDN から読み込み、AWS などの図形と `img/lib/...` の相対画像パスに対応する。CDN が遮断された場合は同梱 SVG の画像表示へフォールバックする。Notion 実環境での対話操作は未検証。

## 7. 状態、復旧、排他

同期情報は Markdown の frontmatter または HTML コメントに保存し、親・ページ ID、本文・メディアのハッシュ、メディアブロック ID などを保持する。共有ディレクトリと作成保留は、正規化した同期元パスの SHA-256 と親 ID ごとに保存する。保存先は macOS では `~/.notion-sync/`、その他では `$XDG_CONFIG_HOME/notion-sync/`。macOS は `XDG_CONFIG_HOME` を使わず、その他では未設定または相対パスなら `~/.config/notion-sync/` を使う。

新しい状態がない場合は同期元内の旧形式 `.notion-sync/state-<親ID>.json` を読み、実行時に新しい場所へ保存する。旧ファイルは削除せず、dry-run は状態を保存しない。同期元の移動・コピー後は最新の共有状態を引き継ぐまで同期しない。古い旧形式ファイルにフォールバックし、作成保留やディレクトリの対応先を見落とす危険がある。同期済みファイルを異なる親で使う場合は停止する。

ページ作成前に保留状態を保存する。作成結果が不明な場合は自動で再作成せず、Notion で確認後に `recover --page-id` または `recover --not-created` で解決する。復旧後の次回同期は本文をローカルの内容で置き換える。保留中の対象は `reset` できない。

`reset` は対象のローカル ID と同期メタデータを消去するが、Notion ページは変更しない。ディレクトリを再帰的に処理し、`--include` / `--exclude` は受け付けない。`--dry-run` で対象を確認できる。

同期・復旧・reset は、同じユーザーと OS の一時ディレクトリを使うプロセス間でロックする。異なる `TMPDIR` を使うプロセス同士は排他されない。対応 OS では、所有プロセスが終了した古いロックの削除を次回実行時に確認する。

## 8. Notion API と障害時の扱い

API は `ntn api` に JSON を標準入力で渡して実行し、応答を検証する。1 回の `ntn` 実行には既定で 60 秒のタイムアウトを設ける。GET は一部の一時的エラーについて最大 2 回再試行する。429 / 529 は `Retry-After` を確認できる場合に限る。Notion 側が要求をブロックした場合や書き込み要求は自動再試行しない。

ページ作成、更新、アップロードなどの結果が不明な場合、重複や上書きを避けるため Notion 上の状態を確認してから復旧する。競合、必須引数不足、検証不能な応答、処理のスキップなどは非 0 の終了コードとなる。

## 9. 制限と検証

- 複数データソースを持つ DB は対象外。Notion の Markdown 変換とワークスペースの制限が適用される。
- Notion ページの自動削除・アーカイブ・移動、一般の添付ファイル、一般的な双方向同期には対応しない。
- Mermaid のコードブロックは Markdown として同期できるが、Notion UI の Preview / Split 表示モードは本ツールから指定しない。
- 実装上の詳細は [同期処理](../internal/sync/engine.go)、[DB プロパティ処理](../internal/sync/properties.go)、[Notion CLI 実行処理](../internal/notion/runner.go) を参照する。
- 開発時の検証は `go test ./...`、必要に応じて `make test` と `make lint` を使用する。`make lint` は golangci-lint と govulncheck を実行する。
